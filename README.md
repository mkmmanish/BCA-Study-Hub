# BCA Study Hub

A responsive student study space and administrator content desk for BCA courses. The local build includes a React interface, an Express JSON API, and persistent SQLite storage.

## Run locally

1. Install Node.js 20 or newer.
2. Copy `.env.example` to `.env` and set a long, random `JWT_SECRET`. The server can start without the file for a temporary demo; in that case, it creates a process-only secret and logs a warning.
3. Run `npm install`, then `npm run dev`.
4. Open `http://localhost:5173`.

`npm run build` creates the production client bundle. `npm start` serves the API and, after a build, the static app from port 4000.

The database is created at `data/study-hub.sqlite`; uploaded files are kept in `uploads/`. Keep both out of source control and back them up according to your institution's retention policy.

## Deploy to Render

1. Push this project to a GitHub repository you control, then select **New > Blueprint** in Render and connect that repository. Render reads `render.yaml` to build and run the app.
2. During Blueprint setup, provide `ADMIN_EMAIL` and a unique `ADMIN_PASSWORD` of at least 12 characters. Set these in Render's secret environment-variable prompt; do not commit them. `JWT_SECRET` is generated by Render.
3. Create the service with the configured persistent disk. SQLite data and uploaded files are stored under `/var/data`; the service uses a single instance because its SQLite database is local to that disk.
4. After the first deployment, sign in using the admin credentials you supplied, create student accounts, and publish institution-approved course materials.

Production startup does not create the local demo accounts or illustrative sample materials. Keep the initial admin password: changing `ADMIN_PASSWORD` in Render later does not rotate an already-created account; change it through the authenticated password endpoint instead. Use HTTPS, keep the disk attached, and arrange separate backups before storing real student data. For a multi-instance deployment, migrate SQLite and local uploads to managed shared services first.

## Seeded local accounts

| Role | Email | Password |
| --- | --- | --- |
| Student | `student@bcastudyhub.edu` | `Study123!` |
| Administrator | `admin@bcastudyhub.edu` | `Admin123!` |

These credentials are **local development only** and are not created in production. Seeded course listings and notices are illustrative; sample past-paper listings are not actual exam papers. Supply only institution-approved materials. Verify that reference links are legal/open access before publishing them.

## Included

- Student registration (email or college ID) and role-specific sign-in, bcrypt password hashes, signed JWT sessions, profile and password updates, and role-protected admin endpoints.
- Materials searchable by title, subject, topic, unit, and description, with year/semester, subject, and type filters.
- Notes, past-paper listings, official YouTube embeds, assignments, practicals, important questions, and external references.
- Admin material create/edit/delete and file uploads (PDF, TXT, ZIP; 20 MB limit), student account create/edit/delete, subject/semester management, exam timetable, notices, and dashboard totals.
- Student bookmarks, recent-material history, completion tracking, course notices, assignment deadlines, administrator-published exam dates, quizzes with saved scores, and a dark/light theme.

YouTube videos are embedded from YouTube; the app does not download or rehost them. PDF/file downloads require an authenticated session. Student accounts can see only their current year's semester materials.

## Recovery and production setup

Password changes are available from a signed-in student profile. Email-based forgotten-password recovery is intentionally not enabled in this local build because no mail provider or verified college identity service was supplied. Add a verified, expiring recovery-token delivery flow before offering self-service account recovery.

Before production, provide a stable secret through `JWT_SECRET`, replace the demo credentials, configure an explicit trusted `CLIENT_ORIGIN`, enable HTTPS, add login throttling and operational monitoring, validate institution-specific account policies, and review file retention, backups, privacy, and content licensing.
